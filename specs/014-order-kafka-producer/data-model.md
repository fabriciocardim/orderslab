# Data Model: order-api como Produtor Kafka

## Entidade existente: `Order` (tabela `orders`)

Sem alteração de esquema. Muda apenas o acesso: `confirm`/`cancel` leem o pedido com
`PESSIMISTIC_WRITE` (`SELECT ... FOR UPDATE`). Estados: `PENDING → CONFIRMED | CANCELLED`
(inalterado; qualquer outra transição segue lançando `InvalidStatusTransitionException` → 409).

## Nova entidade: `OutboxEvent` (tabela `outbox_events`)

Registro de um evento ainda **não entregue** ao broker. Existe só enquanto pendente: é removido
após o ack do Kafka.

| Coluna | Tipo SQL | Nulo | Regra |
|---|---|---|---|
| `id` | `BIGINT GENERATED BY DEFAULT AS IDENTITY` | não | PK; define a ordem de entrega (pode ter lacunas) |
| `event_id` | `UUID` | não | **UNIQUE**; é o `eventId` do payload, estável entre reentregas |
| `event_type` | `VARCHAR(50)` | não | `OrderCreated` \| `OrderConfirmed` \| `OrderCancelled` |
| `topic` | `VARCHAR(100)` | não | `order.created` \| `order.confirmed` \| `order.cancelled` |
| `aggregate_id` | `UUID` | não | `orderId`; usado como **chave Kafka** |
| `payload` | `TEXT` | não | JSON já serializado (Jackson 3), igual ao fio |
| `trace_id` | `VARCHAR(64)` | sim | `traceId` do MDC no enqueue (origem); null se não houver trace |
| `occurred_at` | `TIMESTAMPTZ` | não | momento da transição (mesmo valor do `occurredAt` do payload) |
| `created_at` | `TIMESTAMPTZ` | não | momento da gravação no outbox |

Índice: a PK em `id` atende o `ORDER BY id`. Sem outros índices (tabela só tem pendentes).

Migração: `V2__create_outbox_events_table.sql`. Mapeamento JPA com `ddl-auto=validate`
(mitigação documentada na Decisão 3 se `TEXT`→`String` falhar:
`@JdbcTypeCode(SqlTypes.LONGVARCHAR)`).

### Ciclo de vida

```text
transição validada ─(mesma transação)→ INSERT outbox_events ─commit→ pendente
pendente ─relay: send + ack→ DELETE (mesma transação do relay) → entregue (some do banco)
falha no send → linha permanece; lote encerra; próximo ciclo reenvia (mesmo event_id)
queda entre ack e commit do DELETE → linha permanece → reenvio (duplicata, mesmo event_id)
```

## Eventos (payloads) — ver [contracts/order-events.md](./contracts/order-events.md)

| Classe | Envelope | Campos específicos |
|---|---|---|
| `OrderCreated` | sim | `customerId` (String), `amount` (BigDecimal) |
| `OrderConfirmed` | sim | — |
| `OrderCancelled` | sim | — |

Regras de geração: `eventId = UUID.randomUUID()` no enqueue; `eventVersion = 1`;
`occurredAt` = instante da transição (para `create`, `createdAt` do pedido; para
`confirm`/`cancel`, `updatedAt` após o `setStatus`); `orderId = order.getId()`.

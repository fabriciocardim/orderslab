# Data Model: invoice-api como Consumidor e Produtor Kafka

## Entidade existente evoluída: `Invoice` (tabela `invoices`)

Colunas atuais (V1): `id UUID PK`, `order_id VARCHAR(255) NOT NULL`, `payment_id VARCHAR(255) NOT
NULL`, `amount NUMERIC(19,2) NOT NULL`, `status VARCHAR(20) NOT NULL`, `created_at`/`updated_at
TIMESTAMPTZ NOT NULL`.

Mudanças (migração `V2__invoice_event_support.sql`):

| Mudança | Detalhe |
|---|---|
| Nova coluna `source_event_id` | `UUID`, **nula**; preenchida só em notas decididas a partir de `PaymentReserved` (o `eventId` de entrada). Nula nas criadas por `POST /api/invoices`. |
| Índice único `ux_invoices_source_event_id` | em `(source_event_id)` — dedup por `eventId` (FR-004). |
| Índice único parcial `ux_invoices_order_id_from_event` | em `(order_id) WHERE source_event_id IS NOT NULL` — no máximo uma nota decidida por evento por pedido (FR-005); não afeta notas REST. |

`InvoiceStatus` ganha `FAILED` (além de `PENDING`, `ISSUED`, `CANCELLED`). Transições:

```text
REST:  PENDING → ISSUED | CANCELLED                                   (inalterado)
evento PaymentReserved, valor <= limite → ISSUED (nasce emitida)
evento PaymentReserved, valor >  limite → FAILED (terminal)
```

`issue`/`cancel` de `FAILED` (ou de `ISSUED` criada por evento) lançam o
`InvoiceNotFound/InvalidStatusTransitionException` já existente conforme o caso (409 para
transição inválida). `InvoiceResponse` não muda; só passa a poder trazer `"FAILED"`.

## Nova entidade: `OutboxEvent` (tabela `outbox_events`)

Mesmo esquema do E2.2/E2.3 (ver [`specs/015.../data-model.md`](../015-payment-kafka-consumer-producer/data-model.md)),
criado no `invoice_db` na `V2`: `id BIGINT GENERATED BY DEFAULT AS IDENTITY PK`, `event_id UUID NOT
NULL UNIQUE`, `event_type VARCHAR(50) NOT NULL` (`InvoiceIssued` | `InvoiceFailed`), `topic
VARCHAR(100) NOT NULL` (`invoice.issued` | `invoice.failed`), `aggregate_id UUID NOT NULL`
(`orderId`, chave Kafka), `payload TEXT NOT NULL`, `trace_id VARCHAR(64)` (nulo), `occurred_at
TIMESTAMPTZ NOT NULL`, `created_at TIMESTAMPTZ NOT NULL`. Removido após o ack.

## Eventos — ver [contracts/invoice-events.md](./contracts/invoice-events.md)

| Classe | Direção | Campos específicos |
|---|---|---|
| `PaymentReservedMessage` | entrada | `paymentId` (UUID), `amount` (BigDecimal) + envelope |
| `InvoiceIssued` | saída | `invoiceId` (UUID), `paymentId` (UUID), `amount` (BigDecimal) |
| `InvoiceFailed` | saída | `paymentId` (UUID), `reason` (String, `AMOUNT_ABOVE_ISSUANCE_LIMIT`) |

`eventId = UUID.randomUUID()` no enqueue; `eventVersion = 1`; `occurredAt` = `createdAt` da nota;
`orderId` = o do `PaymentReserved` de origem.

## Fluxo de processamento (uma transação)

```text
parse JSON ── inválido / campo obrigatório ausente / amount <= 0 ──→ log ERROR, retorna
   ▼ (válido)
BEGIN
  existsBySourceEventId(eventId) ou existe nota-de-evento para orderId ──→ log "duplicate", COMMIT
  decisão = InvoiceDecisionPolicy(amount)           // amount > limite ⇒ FAILED
  INSERT invoices(... status = ISSUED|FAILED, source_event_id = eventId)
  INSERT outbox_events(InvoiceIssued | InvoiceFailed)
COMMIT ──→ offset confirmado depois
erro transitório ──→ exceção; DefaultErrorHandler repete (1 s, ilimitado)
violação de constraint (corrida) ──→ rollback; reentrega; pré-checagem acha duplicata
```
